# CAD Guardian Paid Engagement Workflow Command Center

Public route: `https://tsmithcode.github.io/bdpc/cadguardian-engagement-workflows/`

## Purpose

This static, mobile-first sales and delivery corpus gives a business-development manager, salesperson, marketer or delivery leader a governed way to discuss and qualify CAD Guardian engagements.

The public interface is backed by:

- `data/corpus.json` — fourteen paid workflows, commercial ladder and proof rules.
- `data/operations.json` — Stripe architecture, IVR, sales operation and public-safe enterprise pursuit pattern.
- `app.js` — accessible client-side rendering and workflow filtering.
- `styles.css` — purple CAD Guardian visual system derived from the approved shield/image direction.

## Commercial truth

The site deliberately does not contain invented Stripe Payment Links. Before activating any live payment path, reconcile:

1. Approved catalog/SKU and effective version.
2. Scope, exclusions, inputs, acceptance and capacity.
3. Public route and proposal/SOW template.
4. CRM product and amount mapping.
5. Stripe product, price, payment mode and metadata.
6. Invoice/delivery/receipt record.

Payment confirms an accepted scope; it never expands scope.

## Content governance

- Public claims must be evidence-backed.
- Client attribution requires written permission.
- Recruiting signals are market intelligence, not client wins.
- CAD Guardian does not assume architect- or engineer-of-record authority.
- ROI is modeled from buyer-specific baselines, not generic productivity claims.
- Unknown geometry, design decisions and system ownership remain explicit.

## Mobile and accessibility controls

- 320-pixel minimum viewport support.
- 44-pixel minimum interactive targets.
- Keyboard focus indicators and skip link.
- Reduced-motion and print support.
- No required hover interaction.
- JSON remains directly readable if JavaScript is unavailable.
- Responsive tables and one-column phone layouts.

## Deployment

The parent `tsmithcode/bdpc` repository already publishes GitHub Pages from `gh-pages`. The root workflow mirrors canonical `main` to that branch. This subsite is isolated at `cadguardian-engagement-workflows/` and does not replace the existing BDPC root experience.
